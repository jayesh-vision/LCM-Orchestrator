🚨 Why the Legacy Schema Failed (5 Critical Baseline Findings)
Critical 1. First Normal Form (1NF) Violation: Comma-Separated Values in Single Cells
CALL_FLOW · COMMISSIONING_FLOW
In CALL_FLOW, the columns NOTIFICATION_EMAILS varchar(1000) and ASSOCIATED_WORKFLOWS varchar(2000) store comma-separated lists of recipients and workflow names. Similarly, COMMISSIONING_FLOW.COMMAND_INPUTS text stores unstructured CSV params. This makes indexing impossible, forces full-table scans with LIKE '%email%', and prevents relational joins or referential integrity checks.
Critical 2. Broken Multi-Tenancy & Missing Foreign Keys on Catalog Parameters
SERVICE_CATALOG_PARAMETER · NS_NE_MAPPING
SERVICE_CATALOG_PARAMETER has a column SERVICE_CATALOG_ID, but there is no FOREIGN KEY constraint linking it to SERVICE_CATALOG.ID. Furthermore, CUSTOMER_ID is present on some tables but omitted on child tables, permitting cross-tenant parameter access and phantom data pollution where tenant A can see tenant B's catalog params.
Critical 3. Charset Fragmentation: Deprecated utf8mb3 Mixed with utf8mb4
13 Tables in utf8mb3 · 18 Tables in utf8mb4
Thirteen core tables (e.g., CALL_FLOW, PROFILE_TYPE, CALL_FLOW_CATEGORY) use MySQL's deprecated utf8mb3 charset, while the other 18 use utf8mb4. Joining a utf8mb3 column with a utf8mb4 column disables index lookups in MySQL, causing implicit type conversions and full-table scans. Additionally, utf8mb3 silently truncates 4-byte UTF-8 data (modern symbols, emojis).
Critical 4. Drifted Hibernate Envers Audit Tables Without Foreign Key Parity
CALL_FLOW_STATUS_AUD · COMMISSIONING_JOB_AUD · LCM_AUDIT
Six audit tables (e.g. CALL_FLOW_STATUS_AUD, COMMISSIONING_JOB_AUD) generated via Envers contain columns that have completely drifted from their primary base tables. Columns added to base tables are missing from the AUD tables, causing production runtime write failures whenever an audited entity triggers an update event.
Critical 5. Unmaintainable 49-Value Hardcoded Enum on Callflow Statuses
CALL_FLOW.DEFAULT_STATUS
CALL_FLOW.DEFAULT_STATUS has an ENUM definition with 49 string literals (ACTIVE, ADD, APPROVED, COMPLETED, DECOMMISSIONED, DELETED_SERVER, TO_DISBALE [typo in DDL!], etc.). In MySQL, altering an ENUM with 49 values locks the table for writes. Misspellings like TO_DISBALE in production DDL prove the fragility of monolithic unconstrained ENUMs.
✅ What the Redesign Does Exceptionally Well (9.3 / 10 Strengths)
⚡ Clustered PK Architecture (ADR v2.0)
Sequential UUID v7 and TSID rightmost append eliminates InnoDB 50% B-tree leaf page splits. Zero random UUID v4 inserts, achieving near AUTO_INCREMENT write speeds.

🔎 Redesign Findings & SQL Remediation (6 Minor Observations)
Minor 1. Missing Numerical Range CHECK Constraints
WORKFLOW · SERVICE · QUEUE
MySQL 8.0 natively enforces CHECK constraints. Adding defensive bounds on telecom percentages, capacities, and priorities prevents corrupt UI charts (e.g. FIRST_PASS_RATE exceeding 100.00% or PRIORITY outside 1-10).
SQL Remediation 
ALTER TABLE WORKFLOW 
  ADD CONSTRAINT CHK_WF_PASS_RATE CHECK (FIRST_PASS_RATE >= 0.00 AND FIRST_PASS_RATE <= 100.00);

ALTER TABLE DEVICE_EXECUTION_QUEUE 
  ADD CONSTRAINT CHK_QUEUE_PRIORITY CHECK (PRIORITY BETWEEN 1 AND 10);

ALTER TABLE SERVICE 
  ADD CONSTRAINT CHK_SVC_BANDWIDTH CHECK (BANDWIDTH_MBPS > 0);
Minor 2. Missing Composite Uniqueness on Live Service Attributes
SERVICE_ATTRIBUTE
A customer circuit should have at most one audited entry per attribute name (e.g. Bandwidth, VLAN). Adding a composite unique key prevents duplicate drift rows during concurrent scans.
Verification Query & Remediation 
-- 1. Verify no duplicates exist
SELECT SERVICE_ID_FK, ATTRIBUTE_NAME, COUNT(*) 
FROM SERVICE_ATTRIBUTE GROUP BY SERVICE_ID_FK, ATTRIBUTE_NAME HAVING COUNT(*) > 1;

-- 2. Add Composite Unique Key
ALTER TABLE SERVICE_ATTRIBUTE 
  ADD CONSTRAINT UK_SVC_ATTR_NAME UNIQUE (SERVICE_ID_FK, ATTRIBUTE_NAME);
Minor 3. Dual-Nullable FKs Allow Potential Orphan Endpoints
SERVICE_ENDPOINT
SERVICE_ENDPOINT correctly supports both in-flight requests (via PROVISIONING_REQUEST_ID_FK) and live circuits (via SERVICE_ID_FK). Adding a CHECK constraint guarantees an endpoint is never unanchored.
SQL Remediation 
ALTER TABLE SERVICE_ENDPOINT 
  ADD CONSTRAINT CHK_ENDPOINT_PARENT CHECK (
    (SERVICE_ID_FK IS NOT NULL) OR (PROVISIONING_REQUEST_ID_FK IS NOT NULL)
  );
Minor 4. Missing Composite Uniqueness on Request Deltas & Task Rules
REQUEST_DELTA · TASK_VALIDATION_RULE
A Day-2 change request should record only one diff row per attribute, and validation rules within a task should have unique sequence numbers.
SQL Remediation 
ALTER TABLE REQUEST_DELTA 
  ADD CONSTRAINT UK_DELTA_REQ_ATTR UNIQUE (PROVISIONING_REQUEST_ID_FK, ATTRIBUTE_NAME);

ALTER TABLE TASK_VALIDATION_RULE 
  ADD CONSTRAINT UK_RULE_TASK_SEQ UNIQUE (WORKFLOW_TASK_ID_FK, SEQUENCE);
Minor 5. High-Frequency Runs Drawer Relies on Implicit FK Indexing
RUN_TASK · ACTIVATION_RUN
While InnoDB creates internal indexes for foreign keys, declaring an explicit composite covering index on (ACTIVATION_RUN_ID_FK, SEQUENCE) ensures sub-millisecond transcript retrieval in the UI Runs Drawer as task logs exceed 10 million rows.
SQL Remediation 
CREATE INDEX IDX_RUN_TASK_EXEC ON RUN_TASK (ACTIVATION_RUN_ID_FK, SEQUENCE);
CREATE INDEX IDX_ACT_RUN_DEV ON ACTIVATION_RUN (NETWORK_ELEMENT_ID_FK, STARTED_TIME);
Minor 6. Documented Controlled Denormalization of External OMS Fields
PROVISIONING_REQUEST · SERVICE
ACCOUNT_NAME, MONTHLY_VALUE_INR, and TRAFFIC_IMPACT are stored directly in LCM tables rather than fetched dynamically from the external Order Management System (OMS) via REST Feign clients. This intentional hybrid cache avoids network latency on Screen 1 and Screen 2 rows.
